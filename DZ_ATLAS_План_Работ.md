# Локальный торговый терминал «Атлас» — план работ

**Версия:** 1.0 (2026-09-28)
**Исполнитель кода и документации:** Claude (Opus). **Младшая модель:** только администрирование, раздел 5.
**Порядок сдачи:** порциями; следующая порция — после подтверждения руководителем.

---

## 1. Реестр задач руководителя

Каждая задача из ветки с младшей моделью получила номер и решение. «Принято» — делаю как задумано; «с изменением» — делаю, но иначе, по указанной причине.

| № | Задача | Решение |
|---|---|---|
| R01 | Сторож-архиватор: копия при каждом сохранении и компиляции, версии без перезаписи, суточные папки, журнал удалений | **Принято.** Порция 1 |
| R02 | Автозапуск сторожа вместе с Windows, без окна | **Принято.** Порция 1 |
| R03 | Сторож охраняет и хранилища данных и сертификатов | **Принято.** Порция 1, в конфигурации |
| R04 | П11: данные сертифицируются один раз, хранятся только для чтения, с отпечатком SHA-256 | **Принято.** Порция 2 |
| R05 | Сертификат данных по всем таймфреймам M1…M240 и пользовательским | **С изменением:** источник истины — M1. Старшие таймфреймы — производный кэш той же функции ресемплинга (постулат П7), с отпечатком и версией функции в сертификате |
| R06 | Потенциал рынка по свингам | **С изменением:** величина зависит от порога свинга, поэтому порог записывается в сертификат. Это описательная статистика, а не «100% потенциала» |
| R07 | Паспорт инструмента: тик, пункт, издержки, минимальный безубыток, лимиты, окна | **Принято.** Порция 2. TickSize и PointValue — из манифеста выгрузки NinjaTrader, а не вручную |
| R08 | Шлюз аудита: проверка постулатов и штамп на каждом отчёте | **С изменением:** проверка постулатов = печать эмулятора (отпечатки + регресс до цента), а не поиск имён классов в тексте. Порция 2 |
| R09 | Сертификатор шаблонов: пределы и конфликты параметров | **С изменением:** правила пишутся для настроек S021, а не S019 — `ScaleSteps`, `KeepRunner`, `StopLossDollars` в S021 нет. Порция 2 |
| R10 | Хранилище по инструментам и стратегиям | **Принято.** Порция 3 |
| R11 | Светофор инструментов и стратегий: красный, жёлтый, зелёный, золотой | **С изменением:** статус пишется в файл состояния и в пульт. **Папки не переименовываются** — иначе рвутся пути скриптов, NinjaTrader и Excel |
| R12 | Восемь обязательных элементов стратегии, включая исходник C# | **Принято.** Порция 5 |
| R13 | Скрипт бэктеста — в органайзере инструмента, не в папке стратегии | **Принято** |
| R14 | Сертификация библиотеки: золото — первоисточник, зелень — перекрёстная проверка | **Принято.** Порция 5 |
| R15 | Горячая папка DROP_ZONE: раскладка по имени, только чтение, самоочистка | **С изменением:** диспетчер **никогда не пишет в `bin\Custom`** — туда кладёт только руководитель, иначе запустится компиляция чужого кода. Порция 3 |
| R16 | Excel-пульт: выбор стратегии и инструмента, красные строки дефицита, арбитраж рисков | **Принято.** Порция 4 |
| R17 | Режим воспроизведения рынка — жёлтый допуск | **Принято.** Порция 4 |
| R18 | П12: золото только после 30 дней реальной торговли и сходимости с бэктестом | **С изменением:** 30 сделок статистически ничего не доказывают — погрешность PF на такой выборке больше самого PF. К 30 дням добавляется статистический критерий: доверительный интервал ожидания сделки. Порция 6 |
| R19 | Боевая поставка — скомпилированная сборка через импорт NinjaTrader | **Принято.** Порция 8, с проверкой процедуры по руководству. Исходник остаётся в хранилище: по нему работает исполнитель на ПК |
| R20 | Две ветви: традиционная Надарая–Ватсон и быстрая локальная прямая | **Уже сделано:** `[K51]` в MOD9 и `[H02]` в MOD10 |
| R21 | Выход 2/3 лимитом за свинг + 1/3 бегунок по Калману, фильтр объёма | **Принято.** Порция 7 — нужны исходники Калмана и Lever из вашей сборки |
| R22 | Сглаживатель `DZ_HF_NonparametricSmoother` | **Отклонено как отдельный файл:** это вторая копия MOD9 и MOD10. Йео–Джонсон с λ = 0 на цене не работает, Хёрст на окне 50 — шум. Функциональность уже есть в MOD9 и MOD10 |
| R23 | Аварийная кнопка «закрыть всё» из Excel | **Принято.** Порция 8, через файл команд ATI |
| R24 | Горячая смена параметров без перезапуска стратегии | **Отложено:** смена параметров посреди позиции ломает состояние модулей. Нужен отдельный проект с правилом «только вне позиции» |
| R25 | Поток капитала в Excel в реальном времени | **Принято.** Порция 8, через выгрузку из стратегии |
| R26 | Автоматическая выгрузка истории | **Уже сделано:** `DZ_IND_BarExporter_S021` |
| R27 | Восстановить компиляцию после поломки | **Приоритет.** Этап 0 — нужен архив исходников |

## 2. Поправки к ветке младшей модели

- **Файлов, о которых сообщались «акты приёмки», не существует.** Они появятся в порциях этого плана.
- **Прогноз метрик новой модели не посчитан.** Метрики даст только прогон.
- **«Компилируется без ошибок»** без компиляции не утверждается.
- **Смещение по Хёрсту, YJ на цене, ранний выход Епанечникова** — уже проверены численно в MOD9 и MOD10; выводы там, а не в ветке.

## 4. Общие правила

- **Ничего не удаляется** — только архивируется сторожем.
- **Код меняется только компиляцией в NinjaTrader.**
- **Любое число — вместе с файлами, которые его породили.**
- **Статус — в файлах состояния, а не в именах папок.**

## 5. Роль младшей модели — администрирование

**Разрешено:** запускать скрипты Атласа по командам из документации; класть файлы в DROP_ZONE; читать журналы и отчёты; готовить сводки для руководителя.

**Запрещено:** писать и править код; класть файлы в `bin\Custom`; менять сертифицированные файлы и сертификаты; снимать атрибут «только чтение»; сообщать о файлах, которых она не создала и не проверила.
