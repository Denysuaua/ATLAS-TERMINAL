## 2. Порядок первого запуска

Окно службы v1 закрыть: две службы на одной очереди не работают, служба v2 откажется стартовать.

```
cd /d C:\Atlas_terminal\certification
python DZ_HOUSE_Order_S021.py plan
```

План печатается и сохраняется в `C:\Atlas_terminal\archive\plans\`. На копии архива от 05.10 он такой:

| Правило | Сколько | Куда |
|---|---|---|
| П1 | 38 | побайтные дубли корня → `archive\<дата>_порядок\корень` |
| П2 | 3 | пресеты `DZ_PRESET_*.json` → `certification\presets_library` |
| П3 | 13 | отчёты исследований 05.10 → `certification\results\research\2026-10-05` |
| П4 | 1 | дубль «Справочное_Руководство еще старее.md» → архив |
| П5 | 1 | `DZ_TS_Lab_Orchestrator.py` с уничтоженной кодировкой → архив |

`DZ_WATCHDOG_Backup.py` в корне не трогается: сторож может запускаться оттуда планировщиком.

Если план устраивает, выполнить следующие команды:

```
python DZ_HOUSE_Order_S021.py apply --plan "C:\Atlas_terminal\archive\plans\plan_<время>.json"
python DZ_HOUSE_Order_S021.py rotate-token
python DZ_HOUSE_Order_S021.py certify-v2
python DZ_HOUSE_Order_S021.py verify-all
```

Затем запустить службу двойным щелчком по `START_ATLAS_SERVICE_v2.bat` и в соседнем окне выполнить приёмку:

```
python DZ_ATLAS_Ctl_v2.py smoke
```

Что важно знать о каждой команде:

- **apply** перед каждым переносом сверяет отпечаток файла с планом. Файл назначения не перезаписывается. Ничего не удаляется, каждая строка пишется в `archive\MOVE_JOURNAL.jsonl`.
- **rotate-token** нужен, потому что прежний ключ службы был в переданном архиве. После смены ключ в пульт v1 вставляется заново из файла.
- **certify-v2** работает около минуты и занимает до 1,1 ГБ памяти. Сертификат v1 и его файлы не трогаются: на них посчитаны все 13 148 испытаний.
- **verify-all** пишет отчёт `certification\status\HOUSE_REPORT_<время>.md`.

## 3. Что изменилось для оператора

**Пульт v1 работает со службой v2 без правок:** адреса `/task` и `/status` прежние.

- **Задача без конца периода** обрезается замком отложенной выборки до 2022-01-01. Пометка видна в состоянии задачи. Явный заход за дату — отказ. Вскрытие выборки — только с `"unlock_holdout": true` и причиной `"unlock_reason"`.
- **Пресет** теперь делает служба, а не страница: `python DZ_ATLAS_Ctl_v2.py preset <id>`. Страница v1 не переносила постоянные режимы графа `nt_fixed`, поэтому её пресет давал пробой без безубытка и трейлинга. Служба считает пресет формулой оптимизатора, проверяет по схеме меню и пишет в `dz_export\presets`. Имя файла для `[U05]` выводится в ответе.
- **Пресет, который выключает [MOD1] или включает [MOD8]**, отвергается по догме. Для испытания в воспроизведении рынка нужен `--reason "…"` не короче 20 знаков; причина пишется в журнал.
- **Старшие ТФ в сертификате v2** начинаются от 17:00 по Чикаго, то есть от 00:00 по Берлину. В недели, когда США и Европа переходят на летнее время в разные даты, начало — 23:00 по Берлину. 4H-бары открываются в 00, 04, 08, 12, 16, 20 часов по Берлину.

## 4. Адреса службы

Все адреса, кроме `/health`, требуют ключ в заголовке `X-Atlas-Token`.

| Адрес | Что делает |
|---|---|
| `GET /health` | служба жива, поток очереди жив, зависимости есть |
| `GET /status` | задачи, зависимости, замок, эксперименты, тревоги |
| `POST /task` | постановка задачи или плана проверки вперёд |
| `POST /cancel?id=`, `POST /requeue?id=` | отмена; повтор под новым id |
| `GET /log?id=&offset=` | журнал расчёта задачи |
| `GET /results`, `/summary?id=`, `/trades?id=`, `/trials?id=`, `/wfa?id=` | результаты; сделки с кривой капитала, годами и долей забранного потенциала (MFE capture) |
| `GET /registry` | испытания по стратегиям, порог «случайного лучшего», сколько осталось до 4σ |
| `GET /certificates`, `POST /verify?what=data\|strategy\|emulator\|passport` | сертификаты и проверки |
| `GET /gates`, `POST /decision` | десять ворот выпуска; отметки ворот 1 и 10 |
| `GET /schema`, `GET /graph`, `POST /preset` | схема меню, граф, пресет для `[U05]` |
| `GET /account` | позиции и связи из `outgoing` NinjaTrader (руководство NT8 §10.4.1.4.2, с. 604–605) |
| `POST /emergency/flatten_all`, `POST /emergency/close_position` | OIF `FLATTENEVERYTHING` и `CLOSEPOSITION` (§10.4.1.4.1, с. 604) со словом подтверждения и проверкой FLAT |
| `GET /bars?symbol=&tf=&from=&to=` | бары из сертифицированных M1, старшие ТФ — очистителем v2 |
| `GET /journal`, `GET /alarms`, `GET /config` | журнал действий, тревоги, настройки |

## 5. Принято и отклонено

**Принято:**

- **Очередь не умирает.** Сбой задачи становится «ошибкой» этой задачи, поток очереди работает дальше.
- **Повтор id — отказ 409.** Прежние результаты не перезаписываются.
- **Отмена и предельное время задачи.** Остановка идёт вместе с рабочими процессами оптимизатора.
- **Журнал расчёта каждой задачи** — `results\_logs\<id>.log`.
- **Перед стартом проверяется**, что интерпретатор видит numpy и pandas. В v1 шесть задач упали с «No module named numpy».
- **Только сертифицированные данные.** Поля `cache` и `data_root` отвергаются: в v1 задача с `cache` считалась на несертифицированном файле, хотя сертификат проверялся.
- **Единицы.** Инструмент подставляется по символу данных; расхождение `base.usd_per_tick` с профилем — предупреждение (проверка №4).
- **Ворота выпуска** считаются из настоящих проверок. Демонстрационный штамп на отчёте из 10 сделок воротами 6 не засчитывается.

**Отклонено и почему:**

| Предложение | Почему нет | Что сделано вместо |
|---|---|---|
| Перезапускать прерванные задачи, как в v1 | молчаливый повтор тратит испытания и может перезаписать частичный результат | состояние «прервана»; повтор — `requeue` под новым id |
| Обрезать периоды и у планов проверки вперёд | окна плана заданы явно; молчаливая обрезка изменила бы схему проверки | отказ с причиной |
| Пересчитать светофор старым `DZ_STATUS_Board.py` | он не сверяет отпечатки и снова покажет «жёлтый» при нарушенном сертификате | ворота `/gates` и `verify-all` |
| Убрать в архив Excel-пульт и копию страницы пульта сейчас | ворота 9 и инструкция оператора опираются на них до порции 2 | перенос — в порции 2 вместе с заменой |
| Завести Git-репозиторий | правило проекта требует сверки с Pro Git до любой рекомендации Git, а книги нет в приложенной базе | отложено до появления Pro Git в сессии |
| Править оптимизатор | вне этой порции; замок для планов закрыт службой без правки `DZ_OPT_WFA.py` | риски перечислены в разделе 8 |

## 6. Экспериментальные функции

Обе выключены. Включаются в `DZ_ATLAS_Service_v2.config.json`.

**Э-Т1 «бюджетный замок»** (`budget_lock.enabled`). Служба отказывает в постановке задачи, если после неё порог «случайного лучшего» превысит `sigma` (4σ) или исчерпан бюджет стратегии из `budgets`. Это критерии №1 и №7 раздела «стоп». Снять замок можно полем `"budget_override"` с причиной не короче 20 знаков; причина пишется в журнал.

Сейчас у стратегии DualBreakout 13 148 испытаний, порог 3,927σ, а 4σ наступает на 17 845 испытаниях. **До 4σ осталось 4 697 испытаний.**

**Э-Т2 «сторож рассинхрона»** (`desync_watch.enabled`). Служба сравнивает позицию стратегии из её сервера пульта с позицией счёта из `outgoing`. Если расхождение держится дольше `grace_sec`, поднимается тревога. При `"action": "pause"` и разрешённых командах `[U03]` стратегии посылается пауза входов. Позицию сторож не закрывает никогда.

Оценивать эксперименты отдельно от основной службы.

## 7. Что проверено и что проверить у вас

**Проверено здесь** (Linux, Python 3.12, numpy 2.4, pandas 3.0, копия архива от 05.10): 54 испытания из 54. В том числе:

- **Доступ:** ключ, Origin, точное совпадение `app://atlas`.
- **Наследие v1:** импорт истории; зависшее «queued» сверено по папке.
- **Результаты:** на прогоне `system_20261001155754` — 3 007 сделок, максимальная просадка −34 081 $, доля забранного потенциала −0,072.
- **Реестр:** порог 3,927σ.
- **Сертификаты и ворота:** см. ниже.
- **Бары 4H:** только часы открытия 17, 21, 01, 05, 09, 13 по Чикаго.
- **Счёт, пресет, отказы:** десять видов отказа при постановке задачи; отказ пресета по догме и пресет с причиной.
- **Очередь:** сквозной прогон на синтетике SYN1 (синтетика — не рынок; это проверка службы, а не исследование); отмена в очереди и во время расчёта без записи в реестр.
- **Аварийные команды:** строки OIF ровно как в руководстве; подтверждение FLAT.
- **Прерывание и сбои:** принудительное закрытие службы во время расчёта и битые файлы очереди.
- **Э-Т1 и Э-Т2:** против макета сервера пульта.

Сертификат v2 на полной истории MGC: M1 v1 и v2 тождественны. Доля старших баров на сетке 17:00:

| ТФ | v1 | v2 |
|---|---|---|
| M240 | 0 % | 100 % |
| M45 | 0 % | 100 % |
| M120 | 66 % (только лето) | 100 % |

**Проверить у вас** (Windows, Python 3.14, NinjaTrader):

1. **`smoke`** — все строки ✅, кроме паспорта сборки, если исходники в терминале новее паспорта 30.09.
2. **Пульт v1** — ставит задачу в службу v2 с новым ключом.
3. **Отмена долгой задачи** — в диспетчере задач не остаётся процессов `python` оптимизатора (`taskkill /T`).
4. **Вторая копия службы** — сообщает, что служба уже работает.
5. **`account`** — показывает файлы позиций вашего счёта. Точное имя инструмента с биржей (например, `MGC 12-26 Nymex`) — то, что нужно для `close`.
6. **Аварийная команда на Sim-счёте** — с позицией 1 контракт. Это не проверено нигде: удаляет ли NinjaTrader обработанный OIF (служба проверяет и это, и FLAT в `outgoing`).
7. **Э-Т2 против настоящего сервера пульта** — `[U01]` включён, воспроизведение рынка или реальное время.

## 8. Известные риски

| Риск | Чем грозит | Что делать |
|---|---|---|
| Оптимизатор пишет реестр через `pd.Timestamp.utcnow()`; pandas 3 предупреждает, что в pandas 4 метод уберут | задача упадёт после всех испытаний, на записи в реестр | правка оптимизатора отдельной порцией: «расчёт испытаний не изменён» и регресс |
| `DZ_OPT_WFA.py` не переносит `unlock_holdout` в окна проверки | без службы v2 план за датой замка не запустится | служба проверяет замок для плана целиком и снимает его только для вскрытого с причиной плана |
| Окно службы закрыто силой во время расчёта | оптимизатор может досчитать сиротой | при следующем запуске задача — «прервана», результат не принимается |
| Папка «Документы» перенесена в OneDrive | служба не найдёт NinjaTrader | указать `nt_root` в настройках |
