## 2. Правила работы — обязательные

1. **Доказательность.** Утверждения о NinjaTrader — только по руководству NinjaTrader 8 и коду. Названия меню, методов и форматов **не придумываются**: не найдено в источнике — так и сказать.
2. **Формат ответа на ТЗ.** Сразу код. Затем — что принято, что отклонено, с доводами. Всегда 2–3 экспериментальные функции, по умолчанию выключенные.
3. **Проверка до выдачи.** Любой код прогоняется: тест, сверка с эталоном, отрицательный сценарий (подмена, отказ). Что нельзя проверить здесь (в среде нет компилятора C#) — помечается прямо.
4. **Перед компиляцией C#** — `DZ_DEV_MemberCheck.py`: откалиброван по настоящему компилятору, ловит поля структур, члены `SwHostView` и число аргументов.
5. **Честность о результатах.** Шум — это шум. «Преимущество не доказано» — нормальный и частый вывод.
6. **Сертифицированные файлы не меняются молча.** Изменение — регресс — новая печать, осознанно.
7. **Безопасность.** Реальный счёт — только после всех ворот выпуска (раздел 8). Режим без ордеров `[E01]` пресет изменить не может.
8. **Одна величина — один источник.** Не переписывать формулу, если она есть: импортировать. Документы с таблицами генерировать из кода, а не писать руками.

## 4. Стратегия в NinjaTrader — `DZ_SW_Hub_S021`

**Коммутатор** — единственная стратегия NinjaTrader и **единственная точка ордеров**. Модули ордеров не подают: они выдают сигналы (`SwSignal`) и требования (`SwAction`), коммутатор решает и исполняет.

**Конвейер на каждом баре серии исполнения:**
1. модули вычисляют и кладут сигналы в свой ящик (`Emit`);
2. коммутатор разбирает ящики (`DrainSignals`, `DrainActions`);
3. команды пульта (`ProcessRemote`);
4. виртуальный стоп и сопровождение (финансовый модуль);
5. исполнение требований;
6. оценка входа (`EvaluateEntry`) — только без позиции;
7. снимок пульту, панель.

**Контракты:**
- `SwModule` — `Attach(SwHostView)`, `Compute(bip)`, `Emit`, `EmitVisual`, `Health`, `Role`, `TelemetryJson`;
- `SwHostView` — **единственный** доступ модуля к платформе. Модуль не трогает `BarsArray` и ордера;
- перечисления меню — только в пространстве `NinjaTrader.NinjaScript`, иначе ломаются обёртки NinjaTrader;
- модуль: файл `DZ_SW_Mod_<Имя>_S021.cs`, классы `Sw<Имя>Config` и `Sw<Имя>Module : SwModule`; буферы — в `Attach`, без выделения памяти на такте.

**Слоты модулей:**

|---|---|---|
| MOD1 | PAC | структура рынка: свинги, сломы |
| MOD2 | TRFP | голосование линий |
| MOD3 | Время | окна сессий, пауза, закрытие дня |
| MOD4 | Режим | режим волатильности |
| MOD5 | Охрана | дневные пределы, блокировки; получает модуль времени |
| MOD6 | Адаптивный стоп | стоп по волатильности |
| MOD7 | Сопровождение по линии | выход по пересечению линии; получает TRFP |
| MOD8 | Двойной пробой | утреннее и вечернее окно; стоп-вход на минутной серии |
| MOD9 | Адаптивное ядро | ядерная регрессия; общий вычислитель |
| MOD10 | Ядро по Хёрсту | ширина окна по показателю Хёрста |

**Меню — 314 настроек в группах 00–17.** Номера групп с ведущим нулём, внутри группы порядок совпадает с порядком индексов. Буквы индексов: S — серии, MOD — слоты, D — решение, E — исполнение, M — модули, F — финансы, P — устаревшее, T — диагностика, W — пробой, K — ядро, L — Лоренц, H — Хёрст, Q — сигнал с ПК, V — визуализация, U — пульт, C — Калман, B — рычаг, G — масса.

**Служебное в коммутаторе:**
- `[U01]`–`[U03]` — WebSocket-сервер пульта на `127.0.0.1`. Ключ, проверка источника, закрытый список команд; команды исполняются в потоке стратегии;
- `[U04]` — выгрузка схемы меню `hub_menu_schema.json` рефлексией;
- `[U05]` — пресет из `dz_export\presets`: всё или ничего, защитные свойства не меняются;
- `[V01]`/`[V02]` — визуальный слой модулей: события принимаются, отрисовка ещё не сделана.

**Метрики оптимизатора:**
- **плато** — лучший по среднему в окрестности ±1 шаг сетки;
- **DSR** — дефлированный Шарп с учётом всех испытаний проекта, ≥ 0,95;
- **PBO (CSCV)** — ≤ 0,5, а для золота ≤ 0,15–0,25;
- **порог «случайного лучшего»** — формула Бейли–Лопеса де Прадо;
- **эффективность проверки вперёд** — ≥ 0,60.

## 6. Лаборатория — как исследуются параметры

- **Классы:** защитные (не исследуются), структурные (гипотезы «вкл/выкл»), числовые (три прохода).
- **Этапы:** 1 — структура и волатильность; 2 — ядра входа; 3 — фильтры; 4 — риск и объём; 5 — выходы. Этап открыт, когда исполнимые параметры прошлых этапов — VALIDATED или REJECTED.
- **Проходы:**
  1. изолированный — одиночный пик ведёт к отказу;
  2. связанный — сделок ≥ 150, PF ≥ 1,35, просадка не хуже −3 500, дрейф ≤ 25%;
  3. проверка вперёд — эффективность ≥ 0,60 и PBO ≤ 0,25.
- **Исполнители:** оптимизатор (12 параметров пробоя), исполнитель модулей на ПК (этапы 1–3), Strategy Analyzer (риск и выходы — `nt-task`/`nt-import`; PBO там не вычислима и заменена долей прибыльных окон ≥ 60%).
- **Бюджет испытаний:** запуск, поднимающий порог «случайного лучшего» выше 4σ, требует `--force`.

## 9. Форматы

- **`task.json`** — `data` (путь или символ), `instrument`, `mode`, `optimize`/`target`/`hypothesis`, `base`, `constraints`, `start`/`end`, `objective`, `max_trials`, `select`.
- **План проверки вперёд** — `{"plan": "DZ-WFA-v1", "task": …, "windows": [{"train", "test"}]}`.
- **`summary.json`** — `best_selected`, `best_plateau`, `best_raw`, `metrics_*`, `deflated_sharpe`, `pbo`, `verdict`, `data_sha256`.
- **Пресет** — `{"preset": "DZ-PRESET-v1", "strategy": "DZ_SW_Hub_S021", "params": {Свойство: значение}}`.
- **Схема меню** — `index`, `name`, `type`, `min`, `max`, `default`, `value`, `group`, `order`, `description`, `enum`.

## 10. Решения — принятые и отклонённые

| Предложение | Решение | Довод |
|---|---|---|
| Порядок экстремумов внутри свечи (O→H→L→C, «фазовый путь») | **отклонено** | по OHLC неизвестен; систематическое смещение |
| Горячая смена параметров внутри позиции | **отклонено** | ломает состояние модулей; есть пауза входов |
| Оптимизировать все 221 (314) настроек | **отклонено** | безопасность и устройство не перебираются; число испытаний обесценивает DSR |
| Метрики RCI, MSI | **отклонено** | не определены |
| `strict_ratio` для связанных параметров | **отклонено** | навязывает связь, которую надо проверить |
| Fleck/Watson, React/Vite | **отклонено** | внешние DLL в NinjaTrader; лишний сборочный конвейер |
| Перевод модулей на `ISwHost` | **заменено** | исполнитель компилирует те же модули со своим `SwHostView` |
| Excel в реальном времени | **заменено** | WebSocket-пульт и служба; Excel не нужен |
| Отдельный сертификатор данных | **заменено** | расширен `DZ_CERT_Data.py` |
| Выбраковка баров без объёма | **изменено** | подсчёт; отказ — по `--strict-volume` |
