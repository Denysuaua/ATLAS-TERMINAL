# DZ_SW_S021 — справочное руководство по эксплуатации

**Версия руководства:** 2.1 (2026-09-21), финальная
**Предыдущие версии:** папка `_history`
**Версия системы:** DZ_SW_Hub_S021-v1.0, модули v1.0
**Платформа:** NinjaTrader 8
**Язык интерфейса:** русский, индексы настроек в квадратных скобках

---

## 0. Как пользоваться этим руководством

Руководство написано одновременно для человека и для обучения модели-помощника. Отсюда три особенности.

**Каждая настройка имеет индекс в квадратных скобках**, например `[F32]`. Индекс совпадает с тем, что видно в окне параметров NinjaTrader. Ссылаться на настройки следует по индексу — названия длиннее и могут быть переведены по-разному.

**Термины используются строго в одном значении.** Раздел 2 содержит глоссарий. Если слово стоит в глоссарии, оно везде означает ровно то, что там написано.

**Различается подтверждённое и непроверенное.** Раздел 15 перечисляет то, что не проверено на платформе. Модель-помощник обязана это учитывать и не утверждать обратного.

## 1. Что это за система

### 1.1. Назначение

`DZ_SW_S021` — стратегия для NinjaTrader 8, построенная как **коммутатор**: одно ядро, к которому подключаются вычислительные модули. Каждый модуль отвечает за одну задачу. Ядро собирает их ответы и принимает решение.

### 1.2. Чем система отличается от прежней Atlas S019

| Свойство | Atlas S019 | S021 |
|---|---|---|
| Точек отправки заявок | десять, в двух файлах | **одна** |
| Обнаружение потери сигнала | нет | **есть**, двусторонний учёт |
| Отказ одного расчёта | останавливал всю стратегию | **изолирован**, остальные работают |
| Режим без ордеров | тестировал не всё | **прогоняет конвейер целиком** |
| Преднастройки и профили | два слоя перезаписи | **отсутствуют** намеренно |
| Число свойств | 437 | около 120 |

### 1.3. Чем система не является

**Не является переносом Atlas.** Числа не совпадут: адаптивный стоп считается другим методом, структура рынка вычисляется заново, профилей нет. Это переработка архитектуры.

**Не является проверенной системой.** Ни один модуль не запускался на платформе. См. раздел 15.

**Не является торговой рекомендацией.** Система исполняет правила; прибыльность этих правил не доказана.

## 2. Глоссарий

| Термин | Значение |
|---|---|
| **Коммутатор** | Ядро системы, класс `DZ_SW_Hub_S021`. Опрашивает модули, сводит решение, ведёт трассировку |
| **Модуль** | Вычислительный блок, наследник `SwModule`. Считает, но ордеров не создаёт |
| **Слот модуля** | Место подключения модуля, настройки `[MOD1]`–`[MOD7]` |
| **Слот пула** | Место объявления дополнительной серии данных, настройки `[S50]`–`[S82]` |
| **Серия исполнения** | Серия, на такте которой принимается решение и отправляются заявки, `[S90]` |
| **Исполнитель** | `SwExecutionModule` — единственный класс, отправляющий заявки |
| **Финансовый модуль** | `SwFinancialManager` — объём, стоп, ступени, безубыток, трейлинг |
| **Роль** | Функция модуля в конвейере: `Signal`, `Filter`, `Sizing`, `Escort`, `Exit` |
| **Сигнал** | Предложение направления сделки. Порождается только модулем роли `Signal` |
| **Вердикт** | Ответ фильтра: `Agree`, `Veto`, `Neutral` |
| **Вето** | Запрет входа фильтром. Одного вето достаточно, чтобы вход не состоялся |
| **Требование** | Просьба модуля `Escort` или `Exit`: перенести стоп либо закрыть |
| **Ящик** | Очередь, куда модуль кладёт результат вызовом `Emit` |
| **Отправлено / принято** | Счётчики `EmitCount` и `CollectCount`. Их расхождение — потеря сигнала |
| **Застой** | Модуль отдаёт сигнал с устаревшим номером бара |
| **Молчание** | Модуль не отдаёт ничего дольше `[T05]` баров |
| **Отказ** | Модуль бросил исключение; изолирован, система продолжает работу |
| **Прогрев** | Период, пока модулю не хватает баров для расчёта |
| **Режим без ордеров** | `[E01]`: заявки не отправляются, ведётся виртуальная позиция |
| **R** | Начальный риск сделки в тиках — расстояние от входа до стартового стопа |
| **Ступень** | Частичное закрытие позиции по достижении заданной прибыли |
| **Подтверждённая ступень** | Ступень, исполнение которой получено от платформы, а не только отправленная |
| **Доллары движения цены** | Изменение котировки, не денежный результат. Для MGC с шагом 0.10: 25 долларов цены = 250 тиков |
| **Берлинское время** | Europe/Berlin с автоматическим переходом CET и CEST |
| **Сессия** | Торговая сессия по шаблону торговых часов инструмента, не календарные сутки |

## 3. Архитектура

### 3.1. Состав

```
DZ_SW_Hub_S021.cs  ─ коммутатор, исполнитель, панель
│
├── финансовый модуль ─ DZ_SW_Financial_S021.cs
│
├── SIGNAL  ─ структура рынка ─── DZ_SW_Mod_Pac_S021.cs
├── FILTER  ─ линии ───────────── DZ_SW_Mod_Trfp_S021.cs
├── FILTER  ─ время ───────────── DZ_SW_Mod_Time_S021.cs
├── FILTER  ─ режим рынка ─────── DZ_SW_Mod_Regime_S021.cs
├── FILTER  ─ риск ────────────── DZ_SW_Mod_Guard_S021.cs
├── ESCORT  ─ адаптивный стоп ─── DZ_SW_Mod_AdaptiveStop_S021.cs
├── EXIT    ─ выход по линии ──── DZ_SW_Mod_EscortLine_S021.cs
└── любая   ─ внешний индикатор ─ DZ_SW_Mod_External_S021.cs
```

### 3.2. Три гарантии архитектуры

**Одна точка заявок.** Вызовы `EnterLong`, `EnterShort`, `ExitLong`, `ExitShort`, `SetStopLoss` встречаются в комплекте ровно по одному разу, внутри исполнителя. Модуль получает не ядро, а урезанное представление `SwHostView` без ордерного API — выставить заявку физически не может.

**Обнаружение потерь.** Модуль кладёт результат в ящик, коммутатор разбирает. Счётчики ведутся независимо; расхождение означает потерю.

**Изоляция отказа.** Исключение в модуле переводит его в состояние `Faulted`. Модуль исключается из решения, остальные продолжают работать. **Восстановление автоматическое:** отказавший модуль опрашивается дальше, и если следующий вызов проходит без исключения, он сам возвращается в рабочее состояние.

### 3.3. Порядок обработки бара

```
1. опрос ВСЕХ модулей на КАЖДОЙ серии
   └─ модуль сам решает, какой такт ему нужен
2. если такт не серии исполнения — выход
3. разбор ящиков, обнаружение потерь, обновление здоровья
4. проверка виртуального стопа (режим без ордеров)
5. финансовый модуль: ступени, безубыток, трейлинг
6. исполнение требований Escort и Exit
7. решение о входе, если вне рынка
8. отрисовка панели
```

**Почему шаг 1 идёт на каждой серии.** Модуль на старшем таймфрейме обязан увидеть закрытие своего бара. Если бы опрос шёл только на серии исполнения, модуль на пятнадцатиминутке никогда не обновил бы состояние вовремя.

**Почему сопровождение до входа.** Открытая позиция важнее нового сигнала.

### 3.4. Как принимается решение о входе

1. Модули роли `Signal` отдают направление и уверенность.
2. Если `[D01]` включено — все готовые сигналы обязаны совпасть. Иначе решает знак суммы.
3. Средняя уверенность сравнивается с `[D02]`.
4. Каждый фильтр даёт вердикт. **Одно вето — вход запрещён.** Фильтр, указавший направление, противоположное сигналу, тоже считается вето. **Неготовый фильтр закрывает вход**: пока хоть один подключённый фильтр прогревается, входов нет.
5. Финансовый модуль рассчитывает объём. Ноль — вход запрещён с причиной.
6. Исполнитель отправляет заявку либо открывает виртуальную позицию.

## 4. Установка

### 4.1. Куда класть файлы

Все десять файлов — в одну папку:

```
C:\Users\<имя>\Documents\NinjaTrader 8\bin\Custom\Strategies\
```

**Ни один файл не кладётся в `Indicators`.** Все — части одной сборки стратегии.

### 4.2. Компиляция

Откройте редактор NinjaScript, нажмите F5. До копирования полного комплекта будут ошибки о ненайденных типах — это нормально.

**Если после копирования всех десяти файлов есть ошибки** — перепишите их из нижней панели редактора с номерами строк. См. раздел 12.

### 4.3. Файлы старых версий

Если в папке остались файлы прежних стратегий с совпадающими именами классов, компилятор выдаст тысячи ошибок `CS0101`, `CS0102`, `CS0229`. Причина — дубликат, а не ошибка кода. Уберите старые файлы из `bin\Custom`.

**Диагностический признак:** номера строк в ошибках больше длины файла — ошибка в сгенерированных обёртках, почти всегда видимость типа.

## 5. Первый запуск — пошагово

### Шаг 1. Включите пул серий

**Это обязательно и это самая частая ошибка.** По умолчанию все четыре слота пула **выключены**, а модули ссылаются на слоты 1, 2 и 3. Невключённый слот уводится на серию графика, и младший со старшим таймфреймом структуры оказываются одной серией.

Включите:

| Настройка | Значение |
|---|---|
| `[S50]` Серия 1 включена | да |
| `[S51]` / `[S52]` | Minute / 1 |
| `[S60]` Серия 2 включена | да |
| `[S61]` / `[S62]` | Minute / 5 |
| `[S70]` Серия 3 включена | да |
| `[S71]` / `[S72]` | Minute / 15 |
| `[S90]` Серия исполнения | 1 |

**Как убедиться:** при загрузке в окне Output должна быть строка

```
[HUB] ссылки модулей на слоты пула: замечаний нет
```

Если вместо неё строки `[HUB-ВНИМАНИЕ] … ссылается на слот N, но этот слот пула выключен` — вернитесь к этому шагу.

### Шаг 2. Оставьте режим без ордеров

`[E01]` включён по умолчанию. **Не выключайте до первого разбора.** В этом режиме система прогоняет весь конвейер на виртуальной позиции.

### Шаг 3. Проверьте слоты модулей

По умолчанию включены:

| Слот | Модуль | По умолчанию |
|---|---|---|
| `[MOD1]` | Структура, сигнал | включён |
| `[MOD2]` | Линии, фильтр | включён |
| `[MOD3]` | Время, фильтр | включён |
| `[MOD4]` | Режим рынка, фильтр | **выключен** |
| `[MOD5]` | Риск, фильтр | включён |
| `[MOD6]` | Адаптивный стоп | **выключен** |
| `[MOD7]` | Выход по линии | **выключен** |

### Шаг 4. Загрузите достаточно истории

Модули требуют прогрева:

| Модуль | Сколько баров своей серии |
|---|---|
| Структура | `2 × [M05] + 2`, по умолчанию 22 |
| Линии | `[M15]`, по умолчанию 100 |
| Режим рынка | `[M22] + 2`, по умолчанию 62 |
| Адаптивный стоп | 60 |

Линии на пятнадцатиминутке при периоде 100 требуют **двадцать пять часов** торговли. Загрузите не меньше недели.

### Шаг 5. Запустите и смотрите панель

Панель в левом верхнем углу. Каждый модуль должен выйти из состояния `ПРОГРЕВ` в `OK`.

### Шаг 6. Снимите стратегию и прочтите итог

В окне Output появится блок `[HUB-ИТОГ]`. Как его читать — раздел 11.

## 8. Модули — подробно

### 8.1. Структура рынка — `[MOD1]`, роль Signal

**Единственный источник направления во всей системе.** Прочие модули только фильтруют, сопровождают или требуют закрытия.

**Что считает.** Опорные экстремумы и три типа событий на двух таймфреймах в двух масштабах:

| Событие | Смысл | Уверенность |
|---|---|---|
| `BOS` | Пробой в сторону действующего тренда — продолжение | 0.40 |
| `CHoCH` | Пробой противоположного экстремума — разворот | 0.65 |
| `CHoCH+` | Пробит и ближний, и предыдущий экстремум — глубокий слом | 0.85 |

Старший таймфрейм добавляет к уверенности 0.10. Итого двенадцать типов: 2 ТФ × 2 масштаба × 3 события.

**Главное свойство — неустранимое запаздывание.** Опорная точка на баре N известна только на баре `N + сила`. До этого момента она не существует. Модуль её не использует раньше. Это плата за то, что уровень реален: обход дал бы прогон лучше достижимого, без ошибки и предупреждения.

**За такт отправляется одно событие** — сильнейшее. Приоритет: тип события, затем старший ТФ, затем свинговый масштаб.

**Событие живёт один такт.** Без сброса один пробой порождал бы вход на каждом последующем баре.

**Первый пробой сигнала не даёт.** Пока тренд не установлен, разворачивать нечего: первый пробой только устанавливает тренд, событие `PAC_TREND_INIT`. Первый сигнал появляется на втором пробое.

**Какие события допускаются во вход по умолчанию:**

| | Внутр. BOS | Внутр. CHoCH | Внутр. CHoCH+ | Свинг BOS | Свинг CHoCH | Свинг CHoCH+ |
|---|---|---|---|---|---|---|
| Младший ТФ | — | да | да | да | да | да |
| Старший ТФ | — | — | — | да | да | да |

### 8.2. Голосование линий — `[MOD2]`, роль Filter

Три линии диапазонного фильтра, каждая на своём таймфрейме. **Направления не порождает — это вето, не сигнал.**

**Алгоритм линии.** Модуль приращения цены сглаживается дважды экспоненциально и умножается на `[M16]` — это ширина диапазона. Линия подтягивается к цене не ближе этой ширины и **никогда не отступает назад**. Направление: вверх, пока линия растёт.

**Главная ловушка, закрытая в коде.** Рекурсия обновляется ровно один раз на закрытии бара своей серии. Обновление на каждом такте коммутатора пересчитало бы сглаживание по нескольку раз за бар и увело бы линию куда угодно.

**Затравка средним.** Пока период не накоплен, сглаженное значение равно среднему накопленного. Без этого к концу прогрева ширина диапазона была бы занижена вдвое.

**Вердикт.** Все голосующие линии в одну сторону — `Agree` с этим направлением. Хоть одна против — `Veto` **любому** направлению: несогласие линий означает отсутствие согласованного движения.

**Нейтраль.** При `CountsAsDisagree` запрещает вход. При `CountsAsAgree` линия не голосует вовсе — а не голосует «за»; иначе одна нейтральная линия определяла бы направление за остальных.

### 8.3. Временные окна — `[MOD3]`, роль Filter

Разрешает вход по времени суток и дню недели. Все времена — **берлинские**.

**Окна по умолчанию:**

| Интервал | Состояние |
|---|---|
| 01:00–08:00 | окно входа 1 |
| 08:00–09:30 | пауза, входов нет |
| 09:30–18:30 | окно входа 2 |
| 18:30–21:30 | новых входов нет, сопровождение |
| после 22:30 | принудительное закрытие позиции, если включено `[M07]` (по умолчанию включено) |
| суббота, воскресенье | входов нет |

**Маршрут времени строгий:** метка бара → UTC по выбранному режиму → Берлин через `TimeZoneInfo`. Метки баров в NinjaTrader лежат в таймзоне, настроенной в платформе, а не у биржи.

**Фиксированного смещения нет намеренно.** Переходы на летнее время в последнее воскресенье марта и октября сдвинули бы все границы на час.

**Отказ разрешения зоны** не приводит к тихой подмене: модуль сообщает о проблеме и перестаёт ограничивать вход.

**Закрытие позиции в 22:30** управляется `[M07]` и по умолчанию включено: удержание через технический перерыв CME несёт риск разрыва. При выключенном `[M07]` в 22:30 только запрещаются новые входы, а позиция остаётся до закрытия сессии.

Границы окон задаются в коде, в классе `SwTimeConfig`, не в окне параметров.

### 8.4. Режим рынка — `[MOD4]`, роль Filter

Отличает три состояния по **отношению дисперсий** приращений:

| Состояние | Признак |
|---|---|
| Возврат к среднему | z значимо отрицательна; движение гасится |
| Блуждание | z в пределах порога; структуры нет |
| Персистентность | z значимо положительна; движение продолжается |

**Почему не тест на единичный корень.** На окне в шестьдесят наблюдений он почти никогда не отвергает нулевую гипотезу независимо от истины.

**Математика проверена численно:** блуждание даёт VR ≈ 0.996 и z ≈ −0.03; возврат к среднему при φ = −0.30 даёт 0.735 и −1.96; персистентность при φ = +0.30 даёт 1.265 и +2.01.

**Длина окна `[M22]`.** При 60 значимым признаётся отклонение VR около 0.26. При 20 — около 0.45, что практически недостижимо.

**Предупреждение по опыту.** На пятиминутном ликвидном индексе рынок близок к мартингалу, и модуль большую часть времени показывает блуждание. **Это ответ, а не дефект.** Снижение порога ради появления других состояний — подгонка под желаемую картинку.

**Внешний источник.** Тест отношения дисперсий не входит в эталонные книги проекта. Принят как классический метод при условии сверки с независимой эталонной реализацией.

### 8.5. Риск — `[MOD5]`, роль Filter

**Последний барьер.** Ни один сигнальный модуль его не обходит.

**Дневной результат считается по сделкам этой стратегии, не счёта.** Ручная торговля и другие стратегии на том же счёте не закрывают исправную позицию этой.

**После перезапуска результат не восстанавливается.** На сборке 8.1.8 проверено: история сделок экземпляра обнуляется при Disable и Enable. По умолчанию `[M34]` блокирует входы до следующей границы сессии.

**Граница дня — начало сессии, не полночь.** Сессия CME начинается в предшествующий календарный день.

**Время новостей сверяется в UTC**, полученном у модуля времени. Новостные паузы поэтому требуют включённого `[MOD3]`.

**При пробитом лимите и режиме `BlockAndFlatten`** требование закрытия повторяется на каждом баре, пока позиция открыта.

**Календарь новостей неполон намеренно.** Даты заседаний центральных банков в коде отсутствуют: ошибка на один день превратила бы фильтр во вредный. Для новостей нужен внешний файл формата `время;значимость;название`, время в UTC.

### 8.6. Адаптивный стоп — `[MOD6]`, роль Escort

Линия защиты, расширяющаяся с волатильностью. Ордеров не создаёт — просит о переносе.

**Отличие от прежнего движка.** Прежний выбирал множитель кластеризацией k средних. Здесь — по **рангу** текущей волатильности среди последних ста значений, три корзины: 2.0, 3.0, 4.0. **Числа с прежним не совпадут.**

**Соглашение о знаке.** Здесь `+1` — бычье состояние, линия под ценой. В прежних движках проекта принято **обратное**. Перепутанный знак не даёт ошибки — он тихо переворачивает логику.

**Защитная сторона.** Модуль просит перенос, только когда линия под ценой для длинной позиции и над ценой для короткой.

### 8.7. Выход по линии — `[MOD7]`, роль Exit

Закрывает позицию при развороте линии против неё либо при пробое её уровня.

**Требует `[MOD2]`.** Получает ссылку на модуль линий, а не считает линию заново: два независимых расчёта одной величины разошлись бы молча.

**Контроль живости зависимости.** Если модуль линий не отправлял ничего дольше 50 баров, выход сообщает `ЗАСТОЙ ЗАВИСИМОСТИ` и перестаёт запрашивать закрытие. Проверяется именно отправка, а не значение: линия диапазонного фильтра стоит на месте в спокойном рынке, и это её нормальное состояние.

**Подтверждение `[M53]`.** Число баров подряд со встречным направлением. Счётчик обнуляется при первом баре в пользу позиции.

При загрузке проверяется порядок границ: база, затем окно сигналов, затем выход, без перехода через полночь. Нарушение печатается предупреждением.

**Минутная серия пробоя `[M84]` обязана быть серией исполнения `[S90]`.** Иначе ордер встанет на минуту позже и пропустит вход на первой минуте окна. При расхождении печатается предупреждение.

**Требует серий M1, 15M и 4H** в пуле `[S50]`–`[S80]`, например `[S82]` = 240 для слота 4.

**Конфликтует с модулем времени `[MOD3]`.** При окнах по умолчанию тот запретит половину утреннего окна сигналов и три четверти вечернего. Для пробоя выключите `[MOD3]`.

**Часовой пояс окон `[M81]` — Chicago, подтверждено.** Метки исходных данных исследования лежат в поясе America/Chicago; это совпадает с открытием Globex после перерыва в 17:00 по Чикаго. Берлинский профиль регламента — отдельная гипотеза: те же часы в Берлине означают другую фазу рынка. Он запускается вторым экземпляром стратегии на втором счёте с `[M81]` = Berlin.

**Метка бара.** NinjaTrader помечает бар временем закрытия. Модуль переводит его во время открытия, чтобы база 06:00–06:59 содержала те же шестьдесят минут, что в исследовании.

**Настройки финансового модуля, воспроизводящие исследование:** `[F11]` = FixedTicks и `[E03]` = **200**; `[F31]` = AtRMultiple, `[F33]` = **0,075** (15 из 200 тиков) и `[F32]` = 1; `[F41]` = FixedDistance, `[F42]` = 0,075; `[F34]` = вкл; `[F07]` = 0,44 на контракт для MGC. Для пробоя выключите `[MOD1]`–`[MOD4]`, `[MOD6]`, `[MOD7]`; риск `[MOD5]` оставьте.

**Стоп исследования — 200 тиков, а не 20.** Метка `FIXED_STOP_PRICE_20` в журналах означает 20 долларов движения цены: выходы по стопу стоят ровно на −200 тиках. На 3 MGC это **600 долларов риска на сделку**, в десять раз больше, чем говорили прежние документы.

**Высокий процент прибыльных при этой конфигурации — свойство конструкции, а не рынка.** На случайном блуждании, где преимущества нет, стоп 200 и безубыток на +15 дают около 90% прибыльных при PF 0,99. Прибыльные сделки мелкие, убыточные — по 200 тиков. Оценивать такую конфигурацию по проценту прибыльных нельзя; значение имеет только PF.

**Результаты исследования недействительны.** Скрипты аудита записывали повторные входы по цене уровня, когда рынок был уже далеко за ним; на случайном блуждании эта логика даёт PF 7,4 из чистого шума. Модуль исполняет правила без этого дефекта: повторный вход — только после возврата цены за уровень, и исполнение не лучше уровня. Подробно — журнал ревизии, раздел 10.

### 8.10. Адаптивное ядро — `[MOD9]`, роль Filter

| Индекс | Назначение | По умолчанию |
|---|---|---|
| `[K50]` | Ядро: Epanechnikov, Triangular, Tricube, Cosine, Gaussian | Epanechnikov |
| `[K51]` | Регрессия: LocalLinear, NadarayaWatson | LocalLinear |
| `[K52]` `[K53]` | Слот серии; ширина окна, баров | 1; 20 |
| `[K54]` | Адаптивная ширина по ATR(20)/ATR(5), в пределах 0,5–2 | вкл |
| `[K55]`–`[K58]` | Вес по объёму, γ, нормировка, окно статистики | выкл, 1,0, Robust, 50 |
| `[K59]` | Порог наклона, тиков на бар | 0,5 |
| `[K60]` | Разворот наклона против позиции: Neutral, Veto, RequestPartialExit | Neutral |
| `[K61]` `[K62]` | Эксперимент: значимость наклона по t-статистике; порог | выкл; 2,0 |
| `[K63]` | Эксперимент: пересечение быстрой и медленной прямых | выкл |
| `[K64]` | Эксперимент: самопроверка предсказательной силы против наивного прогноза | выкл |
| `[K65]` | Режим сигнала вместо фильтра | выкл |

**Zero-GC — гарантия модуля, а не стратегии.** Массивы создаются один раз; на такте бара выделений нет. Панель коммутатора выделяет память при каждой отрисовке.

### 8.11. Классификатор Лоренца — `[MOD11]`

K ближайших ситуаций прошлого по расстоянию Лоренца `d = Σ ln(1 + |xᵢ − yᵢ|)` на пяти признаках: волатильность, скорость Калмана, RSI, плотность объёма, смещение от центра масс. Признаки нормализуются Йео–Джонсоном; λ оценивается по прошлому окну и совпадает с эталоном SciPy. **Сосед голосует, только если его исход уже известен.** Настройки `[L01]`–`[L21]`, группа `10 · Классификатор Лоренца`. **Метод `[L17]` выбирает пользователь:** K ближайших с голосом по знаку исхода; Надарая–Ватсон — взвешенное ядром среднее будущей доходности в ATR по всем допустимым ситуациям, с порогом `[L20]` и минимальным эффективным объёмом выборки `[L21]`; либо согласие обоих. Точность модуль измеряет сам и сравнивает с эталоном «монетки» с той же частотой исхода; `[L13]`, `[L14]`–`[L15]`, `[L16]` — эксперименты.

### 8.12. Ядро с шириной по Хёрсту — `[MOD10]`

Регрессия — вычислитель MOD9, не переписанный. Ширина окна — по показателю Хёрста, исправленному вычетом ожидаемого R/S блуждания на нескольких масштабах. Уровень блуждания оценщика при окне 128 — 0,47, разброс — 0,08. Настройки `[H01]`–`[H15]`, группа `11 · Ядро по Хёрсту`; `[H11]`–`[H14]` — эксперименты.

### 8.8. Внешний индикатор — адаптер

Позволяет подключить любой индикатор NinjaScript без написания нового модуля. Индикатор создаётся в `BuildSlots` ядра, в адаптер передаётся делегат-читатель.

**Обязанность, которую адаптер не берёт.** Если индикатор сам объявляет серии данных, те же `AddDataSeries` обязаны быть продублированы в `State.Configure` коммутатора. Признак: `Mtf` или `MultiTimeframe` в имени.

**`NaN` означает «не готов», не ноль.** Адаптер не подменяет его нулём — иначе неготовность тихо разрешила бы вход.

## 9. Финансовый модуль

### 9.1. Единицы измерения

Внутри модуля всё считается **в тиках**. Деньги возникают только на границе через `TickSize × PointValue`.

| Инструмент | Шаг цены | Стоимость тика | 25 долларов цены это |
|---|---|---|---|
| MGC микрозолото | 0.10 | 1 доллар | 250 тиков |
| GC золото | 0.10 | 10 долларов | 250 тиков |
| SIL микросеребро | 0.005 | 5 долларов | 5000 тиков |

**Ловушка микросеребра.** Доллар движения цены на SIL равен тысяче долларов на контракт. Стоп `[F12]` = 25, нормальный для золота, для серебра означал бы риск 25 000 долларов на контракт.

### 9.2. Расчёт объёма

```
полный риск контракта = стоп в тиках × стоимость тика
                      + издержки круга [F07]
                      + резерв проскальзывания [F08] × стоимость тика

объём = floor(бюджет / полный риск контракта)
```

**При нехватке бюджета модуль возвращает ноль с причиной**, событие `SIZING_BLOCK`. Он не округляет вверх до одного контракта: это означало бы превышение заданного риска на каждой сделке.

**Живой капитал счёта не читается.** Он недетерминирован между прогонами. Используется `[F03]`.

### 9.3. Ступени

**Считаются по подтверждённым исполнениям.** Источник — `OnExecutionUpdate`, номер ступени зашит в имя заявки. Отправленная заявка может быть отклонена, отменена или исполнена частично.

**Мера расстояния `[F23]`.** `RMultiple` — финансово корректная: ступень при 1R означает «заработано столько же, сколько поставлено», независимо от инструмента.

### 9.4. Безубыток и трейлинг

**Отступ безубытка поднимается автоматически** до величины, покрывающей издержки круга. При меньшем значении срабатывание безубыточного стопа приносит убыток. Предупреждение печатается при загрузке.

**Безубыток и трейлинг не спорят.** Оба кандидата вычисляются независимо, берётся тот, что **сильнее сокращает риск**.

**Режимы трейлинга `[F41]`:**

| Режим | Уровень стопа |
|---|---|
| FixedDistance | экстремум минус `[P05]` тиков |
| AtrMultiple | экстремум минус `[F43]` × ATR |
| StepLock | после ступени k — уровень ступени k−1; после первой — цена входа |

### 9.5. Запрет переноса `[F51]`

После первой подтверждённой фиксации подавляет **обе** ветви — и безубыток, и трейлинг. Подавление одной делало бы запрет формальным.

### 9.6. Стоп двигается только в сторону сокращения риска

Исполнитель отклоняет любой перенос, увеличивающий риск. Не отключается. Модуль может просить что угодно — увеличить риск он не сможет.

## 11. Итог прогона

При снятии стратегии в Output печатается блок `[HUB-ИТОГ]`.

### 11.1. Три числа, которые обязаны быть нулём

**Потери сигнала.** Модуль отдавал, коммутатор не получал. Это дефект, а не свойство рынка.

**Отказы модулей.** Любой ненулевой — исключение в коде модуля.

**Расхождение «ступеней запрошено» и «подтверждено»** в режиме без ордеров. Там подтверждение немедленное, и числа обязаны совпасть.

### 11.2. Что допустимо

**Блокировки арбитража** — нормальная работа защиты. Резкий рост означает, что два модуля спорят за один такт.

**Много заблокированных входов** — нормально. Каждый фильтр сужает множество сделок.

### 11.3. Порядок разбора, если входов ноль

Подключайте модули **по одному**:

```
1. только структура        — есть ли сигналы вообще
2. + линии                 — сколько отсеивается
3. + время                 — не режут ли окна всё подряд
4. + риск                  — не блокирует ли перезапуск
5. + адаптивный стоп
6. + выход по линии
```

Подключив всё сразу и получив ноль входов, нельзя узнать, какой фильтр их съел.

## 12. Диагностика неисправностей

### Симптом: тысячи ошибок компиляции

| Коды | Причина | Действие |
|---|---|---|
| `CS0101`, `CS0102`, `CS0229`, `CS0121` | Дубликат класса в папке | Уберите старые файлы с теми же именами из `bin\Custom` |
| `CS0246` на строках больше длины файла | Перечисление объявлено не в том пространстве имён | Перечисления сигнатуры обязаны быть в `NinjaTrader.NinjaScript` |
| `CS0103` о ненайденном типе модуля | Скопирован не весь комплект | Проверьте, что все десять файлов на месте |

### Симптом: входов нет вообще

| Проверка | Где смотреть |
|---|---|
| Включён ли пул серий | Строка `[HUB] ссылки модулей на слоты пула` при загрузке |
| Пройден ли прогрев | Панель: модули в `ПРОГРЕВ`. **Неготовый фильтр закрывает вход для всей системы** — линии на пятнадцатиминутке при периоде 100 прогреваются двадцать пять часов торговли |
| Не блокирует ли риск после перезапуска | Панель, строка риска: `БЛОКИРОВКА ПОСЛЕ ПЕРЕЗАПУСКА` |
| Не вне ли окон по времени | Строка времени на панели |
| Не отсекает ли всё режим рынка | `[M23]` ≠ Any и рынок в блуждании |
| Достаточен ли бюджет | Событие `SIZING_BLOCK` в трассировке |

### Симптом: модуль в состоянии `МОЛЧИТ`

Модуль не вызывает `Emit` на каждом такте серии исполнения. Для собственного модуля: он обязан отправлять `SwSignal.Empty(bar)` даже когда вычислить нечего.

### Симптом: модуль в состоянии `ЗАСТОЙ`

Модуль заполняет `ProducedAtBar` не текущим номером бара. Проверьте, что используется `Host.CurrentBar`.

### Симптом: `ЗАСТОЙ ЗАВИСИМОСТИ` у выхода по линии

Модуль линий `[MOD2]` не опрашивается. Проверьте, что он включён.

### Симптом: события старшего таймфрейма дублируют младший

Слоты `[M01]` и `[M02]` указывают на одну серию. При загрузке печатается предупреждение. Включите пул серий.

### Симптом: стоп не двигается

| Причина | Признак |
|---|---|
| Запрет `[F51]` после первой фиксации | Событие `STOP_SUPPRESSED` |
| Предложенный уровень увеличивает риск | Исполнитель отклоняет молча — это защита |
| Адаптивная линия по неверную сторону | Модуль не просит перенос вовсе |
| Безубыток и трейлинг выключены | `[F31]` = Off и `[F41]` = Off |

### Симптом: безубыточный стоп даёт убыток

`[F32]` меньше издержек круга. При загрузке печатается предупреждение с минимальным значением.

## 14. Частые вопросы

**Почему система не открывает сделок?**
Чаще всего выключен пул серий. Затем — прогрев фильтров: неготовый фильтр закрывает вход для всей системы, и в начале прогона это нормально. Затем блокировка после перезапуска и окна по времени. Порядок проверки в разделе 12.

**Почему в начале прогона входов нет, хотя структура уже даёт сигналы?**
Структура готова через два десятка баров, а фильтр линий — через `[M15]` баров своей серии. Пока фильтр не готов, вход закрыт. Это сделано намеренно: фильтр, открытый при неготовности, отсутствовал бы в самый ненадёжный период.

**Почему числа не совпадают с Atlas S019?**
Это переработка, не перенос. Адаптивный стоп считается по рангу волатильности вместо кластеризации, структура вычисляется заново, профилей нет.

**Можно ли подключить модуль без перезапуска стратегии?**
Нет. Слоты читаются при загрузке. Серии объявляются в `State.Configure` и после запуска не меняются — ограничение платформы.

**Как подключить свой индикатор?**
Через адаптер внешнего индикатора, раздел 8.8. Нового класса писать не нужно.

**Можно ли модулю выставить заявку?**
Нет. Модуль получает `SwHostView` без ордерного API. Это техническая гарантия.

**Что будет, если модуль упадёт?**
Он перейдёт в `ОТКАЗ`, исключится из решения, панель покраснеет. Остальные продолжат работу.

**Почему после перезапуска стратегия не торгует?**
`[M34]` = BlockUntilNextSession. История сделок экземпляра обнуляется при Disable и Enable, дневной результат неизвестен. Входы откроются на следующей сессии.

**Почему режим рынка почти всегда показывает блуждание?**
На пятиминутном ликвидном инструменте это правильный ответ. Проверьте на старшем таймфрейме.

**Можно ли включить реальный счёт?**
Только после полного прогона в режиме без ордеров, разбора итога и проверки на счёте Sim. Раздел 15.

**Почему безубыточный стоп выставлен дальше, чем я задал?**
Модуль поднял отступ до покрытия издержек круга. Иначе срабатывание давало бы убыток.

**Компиляция не проверена.** Статический аудит пройден: скобки сбалансированы во всех десяти файлах, дубликатов классов, перечислений, свойств и индексов нет, модули изолированы от платформы и ордерного API. Но в процессе разработки трижды применялись несуществующие методы платформы — такие ошибки ловит только компилятор.

**Ни один модуль не запускался на данных.** Все утверждения о поведении — о структуре кода, не о результате.

**Прибыльность не доказана.** Ни один прогон не проводился.

**Ревизия версии 2.0 выполнена статически.** Семь дефектов найдены и исправлены чтением кода от выходов к входам; ни одно исправление не проверено запуском. Перечень — в журнале ревизии.

**Совпадение с Atlas S019 не ожидается.**

**Реальный счёт недопустим до:** компиляции без ошибок; прогона в режиме без ордеров с нулевыми потерями и отказами; прогона на Sim-счёте; разбора поведения при частичных исполнениях и переподключении.

## 16. Правила для модели-помощника

Этот раздел адресован модели, обученной на руководстве.

**Не утверждай, что система работает, компилируется или прибыльна.** Ни одно из этого не проверено. Правильный ответ — «это нужно проверить на платформе».

**Ссылайся на настройки по индексу**, например `[F32]`, а не по названию.

**Начинай любую диагностику «входов нет» с пула серий** `[S50]`–`[S80]`. Это самая частая причина.

**Не советуй снижать пороги ради появления сигналов.** Это подгонка под желаемую картинку. Законный путь — увеличить выборку.

**Не советуй включать реальный счёт.** Порядок: режим без ордеров → Sim → решение руководителя.

**Если вопрос выходит за пределы руководства — скажи об этом прямо.** Не придумывай методы платформы NinjaTrader: в процессе разработки такие выдумки уже приводили к ошибкам компиляции.

**Различай доллары движения цены и доллары результата.** Путаница даёт ошибку на порядок, особенно на микросеребре.

**Помни соглашение о знаке.** В адаптивном стопе S021 `+1` — бычье. В прежних движках проекта наоборот.
