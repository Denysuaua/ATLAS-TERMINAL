## 2. Пространства имён — правило

| Пространство | Что в нём | Почему |
|---|---|---|
| `NinjaTrader.NinjaScript` | **перечисления**, видимые в меню настроек (`SwKernelType`, `SwLorentzMethod`, `SwVisualRole` …) | генератор обёрток NinjaScript ищет типы свойств стратегии здесь; перечисление в другом пространстве даёт `CS0246` в сгенерированном коде |
| `NinjaTrader.NinjaScript.Strategies` | коммутатор, модули, их конфигурации, контракты `SwSignal`, `SwAction`, `SwModule`, `SwHostView`, `SwVisualEvent` | модули живут рядом со стратегией, которая их создаёт |

Фактически используются: `NinjaTrader.NinjaScript`, `NinjaTrader.NinjaScript.Strategies`.

### Зависимости через конструктор — модуль получает ссылку на другой модуль

| Модуль | Получает | Зачем |
|---|---|---|
| `SwRiskGuardModule` (MOD5) | `refTime` — модуль времени (MOD3) | границы торгового дня и принудительное закрытие |
| `SwEscortLineExitModule` (MOD7) | `refTrfp` — модуль линий (MOD2) | выход по пересечению линии |

Порядок создания в `BuildSlots` поэтому не произволен: модуль-источник создаётся раньше модуля-получателя. Если источник выключен, получатель получает `null` и обязан это пережить — так написаны все три.

## 9. Правила именования — как написан код

- **Модуль** — `Sw<Имя>Module`, файл `DZ_SW_Mod_<Имя>_S021.cs`; **конфигурация** — `Sw<Имя>Config` с открытыми полями и значениями по умолчанию.
- **Перечисление настройки** — `Sw<Смысл>` в `NinjaTrader.NinjaScript`.
- **Свойство меню** — `PascalCase` с префиксом модуля (`Ker…`, `Lor…`, `Hk…`, `Dbo…`, `Ws…`), атрибут `[Display(Name = "[<Индекс>] …")]`; индекс уникален во всей стратегии.
- **Закрытые поля** — `camelCase` (`execBip`, `bufActions`, `visualRing`); ссылки коммутатора на модули — `ref<Имя>` (`refKer`, `refLor`).
- **Методы коммутатора для хоста** — префикс `Hub` (`HubTrace`, `HubVisual`); модуль видит их только через `SwHostView`.
- **События журнала** — `ПРОПИСНЫЕ_С_ПОДЧЁРКИВАНИЕМ` (`LOR_ATTACHED`, `REMOTE_FLATTEN`, `PRESET_APPLIED`).
- **Экспериментальные настройки** — `…Exp…` в имени и «ЭКСПЕРИМЕНТ» в описании; по умолчанию выключены.

## 10. Как добавить модуль — порядок

1. Файл `DZ_SW_Mod_<Имя>_S021.cs`: `Sw<Имя>Config` и `Sw<Имя>Module : SwModule`.
2. Перечисления настроек — в `NinjaTrader.NinjaScript`.
3. Все буферы — в `Attach`; в `Compute` без `new` (Zero-GC).
4. На каждом такте серии исполнения — ровно один `Emit`; при неготовности — `SwSignal.Empty(bar)`.
5. К платформе — только через `Host`; нужного члена нет — он добавляется в `SwHostView`, а не обходится.
6. В коммутаторе: поле `ref<Имя>`, блок в `BuildSlots`, строка панели, свойства с новым уникальным индексом и значения по умолчанию.
7. Пересоздать эту карту и справочник; компиляция; паспорт сборки `DZ_SYS_Bridge.py snapshot`.
