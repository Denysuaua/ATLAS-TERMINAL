# DZ_PACV025_S021 — логика разметки индикатора PACV025MarketStructureCoreFix: извлечение, перенос, проверка

**Версия:** 1.0 (2026-10-05) · **Источник:** `PACV025MarketStructureCoreFix.cs` (v0.2.7, 1 396 строк), детектор пивотов `PACPivotDetector` из PACCore в файле отсутствует — принят стандартный (центр окна 2L+1, слева строго, справа нестрого, как у PAC проекта) · **Перенос:** `DZ_PACV025_Port_S021.py` · **Проверка:** реестры движений DZ_MOVE, 2015–2018, сертифицированные цены, объём из файлов импорта · **В код:** модуль структуры v1.5, коммутатор v1.20 — эксперименты Э76, Э77, выключены.

## 1. Извлечённая логика

1. **Два контура:** внутренний L = 5 и свинговый L = 50 (у нашего [MOD1] — 3 и 10). Сканер старших ТФ 15/60/240/1440 — та же машина со свинговым L на каждой серии, состояние публикуется в реестр.
2. **Классификация пивота** — по предыдущему пивоту того же типа: High > prevHigh → HH, иначе LH; Low > prevLow → HL, иначе LL. Совпадает с нашей разметкой.
3. **Машина структуры на закрытии бара.** Тренд не определён → первый пробой задаёт тренд без события. В бычьем тренде закрытие ниже последнего пивота Low → CHoCH, причём **CHoCH+ только если перед этим последний пивот High не обновил максимум** (несостоявшийся HH, то есть LH); зеркально в медвежьем. BOS — пробой по тренду, но **засчитывается лишь после первого CHoCH** в истории контура. Уровень засчитывается один раз — флаг «пробит» до нового пивота. Это каноническое определение CHoCH+; у нашего [MOD1] CHoCH+ = пробой за предыдущий уровень (probe > PrevHigh) и BOS без ожидания CHoCH — расхождение зафиксировано.
4. **Сильные и слабые экстремумы, два режима.** VolumeRatio (умолчание индикатора): объём «ноги» — сумма объёма баров между подтверждениями пивотов одного типа — сравнивается с предыдущей такой ногой; min/max ≥ 50 % → Strong (объём сопоставим), иначе Weak (объём изменился более чем вдвое в любую сторону). TrendSide: в медвежьем тренде пивоты High сильные, Low слабые; в бычьем — Low сильные, High слабые; без тренда метки нет. Метка считается всегда и публикуется в реестр, рисуется по флагу.
5. Окраска свечей по тренду и активному событию, линии структуры от пивота до бара пробоя, панель MTF — визуализация, в логику не входит.

## 3. Что внесено в код

- Модуль структуры v1.5: Э76 `ExpChochPlusFailedExtreme` — правила PACV025 (CHoCH+ по несостоявшемуся экстремуму, BOS после первого CHoCH); Э77 `ExpStrongWeak` — режим Off/VolumeRatio/TrendSide: накопление объёма ног, сила подтверждённого пивота, сила пробитого уровня меняет уверенность события на ±`ExpStrongBonus` и пишется в описание сигнала.
- Коммутатор v1.20: [M19], [M20], [M61]; умолчания выключены; отпечаток меню `47e75ce0bb48`. MemberCheck — ошибок нет; StaticCheck — 0 ошибок. Пресеты и задания П7/П8 приведены к v1.20.

Экспериментальные функции порции: Э76 и Э77 в модуле структуры; обе измерены на реестрах до внесения.

Вывод без прикрас: лучшая цепочка даёт около 560 $ в год на контракт при просадке 1 400 $ — отношение PnL/MaxDD 0,4. Цель 66 % годовых при допустимой просадке 25 % капитала требует PnL/MaxDD ≈ 2,6, то есть в **6–7 раз** лучше по форме кривой, а не только по сумме. Отсюда порядок рычагов: 1) выход и защита — захват MFE сейчас 8–10 % при том, что прибыльные сделки берут 60–70 % своего MFE, значит форму портят убыточные с полным стопом; 2) контекст — единственный подтверждённый множитель точности; 3) частота — больше доверенных комбинаций «событие × ТФ» и инструментов после сертификации данных; 4) валидация объёмом — строгие пары. Классификатор и консенсус пяти модулей форму не меняют.

## 4. Задача 2 — цепочки решений под заданные показатели

**Целевые показатели системы (моё решение, к утверждению):** средняя годовая доходность ≥ 66 % капитала; максимальная просадка ≤ 25 % капитала (отсюда PnL/MaxDD ≥ 2,6); PF ≥ 1,5; знак результата положителен не менее чем в 3 из 4 обучающих лет; DSR ≥ 0,95 по реестру испытаний; PBO ≤ 0,2; единственная проверка 2022–2025 проходит без смены знака.

**Грамматика цепочки:** контекст (MOD10-240m / MOD9-60m / MOD13-направление) → триггер (доверенные маркеры [MOD1]) → валидация (MOD14 строгое, MOD11-мета после Э67) → вход (рынок, стоп [E03] или 1 ATR) → защита (MOD13-Б, MOD6, MOD7, 12:30 Б) → выход (переворот, вертикаль, 22:30 для внутридневных) → рубежи и охрана (MOD3, MOD5). Каждый узел несёт индекс взаимодействия из карточки.

**Процедура сборки — отбор вперёд с реестром испытаний:**
1. Старт — C0: доверенные маркеры + стоп + 22:30. Это измеренная база (PnL/год 484 $, MaxDD 1 468 $).
2. Добавление узла по одному в порядке измеренного эффекта: сначала защита (MOD13-Б после подпрохода, MOD6, MOD7, 12:30 Б) — она меняет форму кривой; затем контекст (MOD10-240m, затем MOD9-60m — пара K/D на двух горизонтах); затем валидация (строгое MOD9 + MOD14, Э69); затем охрана (Э4, Э47).
3. Каждая цепочка — одно испытание: метрики целевого набора на обучении, разрез по годам, захват MFE, число сделок. Узел остаётся, если улучшает PnL/MaxDD и не снижает число сделок ниже 100 в год без роста ожидания, и если улучшение держится в 3 из 4 лет.
4. Пороги доверия — по накопленному числу испытаний (DSR, PBO по CSCV), не по лучшей кривой.
5. Расширение частоты: новые доверенные комбинации «событие × ТФ» из реестра и инструменты после сертификации — только после того, как цепочка на MGC проходит целевые пороги на обучении.
6. Проверка 2022–2025 — один раз, по готовой цепочке; смена знака — возврат к п. 2 с новой гипотезой, не подбором.

**Инструменты:** `DZ_CHAIN_Economics_S021.py` — экономика цепочек против цели (капитал на контракт — параметр); `DZ_PORT_Chains_S021.py` — симуляция цепочек с сопровождением; `DZ_CONFLUENCE_S021.py` — вердикты модулей в моменты сигналов; `DZ_OPT_Engine_S021.py` — реестр испытаний, DSR, PBO; `DZ_SA_Audit_S021.py` — аудит прогонов анализатора.

**Версия:** 1.0 (2026-10-04) · Основание: директивы «один модуль — один прогон», паспорт MOD10, реестр этапа 0. Сигналы — утверждённые точки [MOD1] (CHoCH+ 120m, CHoCH+ 60m, BOS swing 120m, BOS 240m). Обучение 2015–2018, проверка 2022–2025 — один раз в конце.

## 1. Постоянные директивы, встроенные в каждый прогон

1. Отрисовка: что модуль рисует на графике и что показывает на дашборде; если не рисует — отметка и кандидат наблюдения.
2. Полное отключение через меню: слот `[MODn]`, при false модуль не создаётся.
3. Сигнал на коммутатор: `Emit` на такте исполнения, вердикт и направление; поля конфигурации передаются (StaticCheck Э34).
4. Экспериментальные функции модуля — отдельной таблицей на робастном профиле, не внутри сетки.
5. После результата — контекстный поиск по базе учебников: что добавить или усовершенствовать.
6. Паритет переноса ядра с NinjaTrader — `parity-dump` против [T13] до заморозки.
7. Индекс взаимодействия ИВ-n — роль, строгость, покрытие по времени, согласие и пересечение с уже испытанными модулями.

## 4. Выводы и решения

1. Связка MOD1 → MOD14/MOD11 как валидация входа в умолчаниях ценности не несёт — измерено на 24 457 кандидатах. Дальнейший перебор их параметров без новой гипотезы — испытания без теории (MLAM, гл. 8).
2. Эстафета MOD1 → MOD9 → MOD13 в умолчаниях вредна из-за сопровождения: тесный стоп по каналу текущего ТФ. Э58 (канал M60) — проверка, не в отступе ли дело.
3. Сам триггер структуры на M5 — монетка: 48,9 % прибыльных кандидатов по тройному барьеру. Это главный факт: никакой фильтр не создаёт ожидания там, где его нет у источника сигналов. Работа переносится на источник: контекст 240m (единственный с положительным знаком) и определение триггера.
4. Все числа — на обучении, порт без паритета; на 2022–2025 не заходили.

## 5. Паритет переноса с NinjaTrader — что сделать на вашей машине

1. На графике MGC M5 с пулом серий M1/M15/M60 (слоты 1/2/3), [MOD1] младший слот 0, старший 2; [MOD9] слот 2; [MOD11] слот 0; [MOD14] анализ 0, кластеры 1; [MOD13] младший 1, текущий 0, старший 3 — два торговых дня Playback, режим без ордеров, [T13] журнал решений включён.
2. На ПК: `python DZ_PORT_Chains_S021.py parity-dump --npz MGC_M1.npz --volume-nt <папка> --start <день> --days 2 --out parity` — те же дни.
3. Сравнить по минутам: события структуры (тип, направление), направление ядра, перевес Лоренца, состояние рычага, состояние и границы Калмана. Расхождения — это либо ошибка переноса, либо порядок тактов; до совпадения числа разделов 2–3 остаются гипотезой.

Экспериментальные функции порции: Э58 — цепочка E2, сопровождение по каналу M60; Э59 — `--meta-horizon N`, горизонт мета-разметки, с N = 4 совпадает с горизонтом Лоренца.

## 2. Главные находки ветки — честный итог

1. Сам триггер структуры в умолчаниях на M5 — монетка (48,9 % прибыльных по тройному барьеру); на 1m–60m отрицательное ожидание после издержек; доверенные комбинации — только 120m/240m, и ни одна не прошла порог множественного выбора.

Вывод: заявленные приросты +13,5…+24,5 пункта WinRate на реальных данных не воспроизводятся — измеренные приросты +0,7…+2,7 пункта; заявленный PF 2,1–2,65 против измеренных 1,19–1,29.
