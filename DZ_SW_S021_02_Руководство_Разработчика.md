# DZ_SW_S021_02 — Руководство разработчика

**Сгенерировано:** DZ_DOC_Dev_S021-v1.0 (2026-10-04) из `DZ_SW_Hub_S021-v1.14 (2026-10-04)`. Руками не править: контракты и такт — из кода.

## 1. Устройство

Одна стратегия — коммутатор `DZ_SW_Hub_S021` — и подключаемые модули `DZ_SW_Mod_*_S021`. Модули считают и голосуют, заявки отправляет только исполнитель внутри коммутатора. Модуль видит ядро через `SwHostView` — представление без ордерного API: вызвать `EnterLong` из модуля невозможно физически. Обмен — через ящики: модуль кладёт `SwSignal` или `SwAction`, коммутатор забирает и сверяет «отправлено — принято»: расхождение — потеря.

## 2. Такт серии исполнения

Порядок шагов `OnBarUpdate` — из кода:

| Шаг | Что происходит |
|---|---|
| 0 | ВИРТУАЛЬНЫЕ ИСПОЛНЕНИЯ — ДО ОПРОСА МОДУЛЕЙ |
| 1 | Опрос модулей НА КАЖДОЙ СЕРИИ |
| 2 | Разбор ящиков и обнаружение потерь |
| 3 | Сопровождение |
| 4 | Исполнение требований |
| 5 | Решение о входе |
| 6 | Панель |

Модули считаются на каждой серии пула; разбор, решение и заявки — только на закрытии бара серии исполнения `[S90]` (руководство NT, с. 2350: заявки — в первый контекст инструмента).

## 3. Контракты

**SwRole:** `Signal` — порождает кандидата направления; `Filter` — накладывает вето; `Sizing` — определяет объём; `Escort` — сопровождение открытой позиции; `Exit` — требование закрытия.

**SwHealth:** `Disabled` — выключен настройкой; `NotAttached` — не создан; `Warmup` — прогревается; `Ok` — работает и отдаёт сигналы; `Silent` — не отдаёт сигнал дольше допустимого; `Stale` — отдаёт сигнал со старым номером бара; `Faulted` — бросил исключение.

**SwActionKind:** `None`; `MoveStop`; `PartialExit`; `FullExit`.

**SwVerdict:** `Neutral`; `Agree`; `Veto`.

**SwSignal**

## 5. Как добавить модуль

1. Файл `DZ_SW_Mod_<Имя>_S021.cs`: класс конфигурации и класс-наследник `SwModule`; версия и дата в шапке.
2. `Compute(int barsInProgress)`: только расчёт и `Emit`. Без выделения памяти в такте, без заглядывания вперёд, без ордерного API.
3. Слот `[MODn]` в коммутаторе: флаг включения, передача настроек в сборке слотов, создание модуля.
4. Настройки меню: индекс `[Xnn]`, русское название и описание, `Range` где есть пределы, умолчание в `SetDefaults`.
5. Одна-две экспериментальные функции, выключенные по умолчанию, со ссылкой на учебник базы проекта.
6. `python DZ_DEV_MemberCheck.py "DZ_SW_*.cs"` — ноль ошибок; затем компиляция F5.
7. `DZ_DOC_Menu_S021.py` и `DZ_DOC_Dev_S021.py` — документы из кода; отпечаток схемы `[T15]` совпадает со справочником.
8. Режим без ордеров с журналом `[T17]`; при наличии эталона на ПК — сверка `parity`.

## 6. Правила

- Одна величина — один источник; вторая реализация — только с перекрёстной сверкой.
- Решение по OHLC не опирается на порядок цен внутри бара; спорный порядок — худший.
- Исключение модуля изолируется: `MarkFault`, модуль снимается, торговля идёт без него.
- Код NinjaScript сверяется с руководством NinjaTrader 8 со ссылкой на страницу.
- Статистика и проверки — по AFML, MLAM и банковской книге; уровни объёма — по Volume Profile.
- Документы 02, 03, 11, 12 генерируются; 00 и 05 ведутся вручную.
